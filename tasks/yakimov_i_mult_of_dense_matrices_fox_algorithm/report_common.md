## Введение

При умножении больших матриц даже самый умный алгоритм работает долго. Чтобы ускорить вычисления, используют параллельное программирование — разбивают задачу на части и считают их одновременно на разных ядрах процессора.

В этой работе я сравнил три технологии распараллеливания:
- **OpenMP** — простые директивы для компилятора
- **TBB** — умная библиотека от Intel
- **STL** — стандартные потоки C++ (всё руками)

Все три версии реализуют один и тот же алгоритм Фокса, поэтому сравнение получается честным.

## Сравнение технологий

### OpenMP

**Как работает:**  
Добавляете `#pragma omp parallel for` перед циклом — компилятор сам распараллеливает.

**Плюсы:**
- Очень просто добавить в существующий код
- Код остаётся читаемым
- Хорошо работает для регулярных циклов

**Минусы:**
- Нужны атомарные операции для общих данных
- При 16+ ядрах эффективность падает

### TBB

**Как работает:**  
Используете `tbb::parallel_for` или `tbb::parallel_reduce` — библиотека сама разбивает работу на задачи.

**Плюсы:**
- Умный планировщик (кража задач)
- Нет атомарных операций (при правильном использовании)
- Отличная масштабируемость

**Минусы:**
- Нужно устанавливать библиотеку
- Код немного сложнее OpenMP

### STL (std::thread)

**Как работает:**  
Сами создаёте потоки, сами делите работу, сами ждёте завершения.

**Плюсы:**
- Полный контроль
- Нет внешних зависимостей
- Подходит для любых компиляторов C++11+

**Минусы:**
- Код сложный и громоздкий
- Нет динамической балансировки (потоки могут простаивать)
- Легко ошибиться

## Сравнительная таблица

| Характеристика | OpenMP | TBB | STL |
|----------------|--------|-----|-----|
| Сложность кода | Низкая | Средняя | Высокая |
| Внешние зависимости | Нет (поддерживается компилятором) | Да (библиотека) | Нет |
| Динамическая балансировка | Нет | Да (кража задач) | Нет |
| Атомарные операции | Да | Нет | Нужно делать самому |
| Ускорение на 1024×1024 | 7.2× | 8.3× | 5.9× |
| Когда лучше использовать | Быстрое прототипирование | Максимальная производительность | Нет других вариантов |

## Выводы

**OpenMP** — лучший выбор для быстрого распараллеливания существующего кода. Особенно если задача имеет регулярную структуру (как алгоритм Фокса). Простота использования перевешивает небольшое отставание в производительности.

**TBB** — лучший выбор, когда нужна максимальная производительность. Планировщик с кражей задач отлично справляется с неравномерной нагрузкой. Если в проекте уже используется TBB — однозначно брать его.

**STL** — выбор для ситуаций, когда нельзя использовать OpenMP или TBB (например, встроенные системы, специфичные компиляторы). Код получится сложнее, но ускорение всё равно будет заметным.

### Итоговая рекомендация

По умолчанию начинайте с OpenMP — это самый простой способ получить ускорение. Если нужно выжать максимум из железа — переходите на TBB. STL используйте только если другие варианты недоступны.
